```bash
      \"BucketKeyEnabled\":true
    }]}"

aws s3 cp main.jpeg  s3://$BUCKET/static/main.jpeg
```

⏱ 즉시. 기본 암호화를 먼저 걸어두면 업로드가 자동으로 KMS로 들어갑니다.

## 8. [콘솔] Lambda

### 8-1. 함수 생성 [일반 셸에서]

```bash
cp lambda.py lambda_function.py
zip -j function.zip lambda_function.py
FN_KEY=$(aws kms describe-key --key-id alias/wsc2026-function-kms --query KeyMetadata.Arn --output text)
ROLE_ARN=$(aws iam get-role --role-name wsc2026-book-function-role --query Role.Arn --output text)

aws lambda create-function \
  --function-name wsc2026-book-get-function \
  --runtime python3.12 \
  --role "$ROLE_ARN" \
  --handler lambda_function.lambda_handler \
  --timeout 30 \
  --kms-key-arn "$FN_KEY" \
  --zip-file fileb://function.zip
```

⏱ **30초**. `--kms-key-arn` 이 채점 7-1의 `KMSKeyArn` 항목입니다.

### 8-2. 환경변수 암호화 ★

`lambda.py` 는 `TABLE_NAME` 을 **KMS 암호문으로 받아 복호화**합니다. 평문을 넣으면 함수가 시작조차 못 합니다.

```bash
CIPHER=$(aws kms encrypt \
  --key-id alias/wsc2026-function-kms \
  --plaintext "$(printf 'wsc2026-book-table' | base64)" \
  --encryption-context LambdaFunctionName=wsc2026-book-get-function \
  --query CiphertextBlob --output text)

aws lambda update-function-configuration \
  --function-name wsc2026-book-get-function \
  --environment "Variables={TABLE_NAME=$CIPHER}"
```

콘솔로 할 경우: **구성 ▸ 환경 변수 ▸ 편집 ▸ 추가 설정** ▸ *전송 중 암호화를 위해 고객 마스터 키 사용* 체크 ▸ `wsc2026-function-kms` 선택 ▸ `TABLE_NAME` 값 옆 **암호화** 버튼 클릭 ▸ 저장.

### 8-3. 실행 역할에 함수 키 복호화 권한 [필수]

`05-dynamodb.sh` 는 함수 키 정책에 `lambda.amazonaws.com` 서비스만 추가합니다. 실제 복호화는 **실행 역할**이 하므로 권한이 하나 더 필요합니다.

```bash
aws iam put-role-policy \
  --role-name wsc2026-book-function-role \
  --policy-name wsc2026-function-kms-decrypt \
  --policy-document "{
    \"Version\":\"2012-10-17\",
    \"Statement\":[{
      \"Effect\":\"Allow\",
      \"Action\":[\"kms:Decrypt\"],
      \"Resource\":\"$FN_KEY\"
    }]}"
```

> **반드시 인라인 정책으로** 넣으세요. `mark.sh` 7-2 는 *연결된 관리형 정책*의 액션만 검사하고 `*` 가 있으면 FAIL 처리합니다. 인라인은 검사 대상이 아니라 안전합니다.

### 8-4. 함수 URL 생성 (CloudFront 원본용)

```bash
aws lambda create-function-url-config \
  --function-name wsc2026-book-get-function --auth-type NONE

aws lambda add-permission \
  --function-name wsc2026-book-get-function \
  --statement-id FunctionURLAllow \
  --action lambda:InvokeFunctionUrl \
  --principal "*" --function-url-auth-type NONE

aws lambda get-function-url-config --function-name wsc2026-book-get-function \
  --query FunctionUrl --output text
```

⏱ 즉시. 출력된 도메인(`xxxx.lambda-url.ap-northeast-2.on.aws`)을 CloudFront 원본에 씁니다.

### 8-5. 동작 확인
```bash
aws lambda invoke --function-name wsc2026-book-get-function \
```

## 12. [콘솔] CloudFront — 원본 3개

**CloudFront ▸ 배포 생성**

### 원본

| # | 이름 | 도메인 | 설정 |
|---|---|---|---|
| 1 | `wsc2026-s3-origin` | S3 버킷 선택 | 원본 경로 **`/static`**, 원본 액세스 **OAC 새로 생성** |
| 2 | `wsc2026-alb-origin` | ALB DNS | **HTTP only**, 포트 80 |
| 3 | `wsc2026-lambda-origin` | 함수 URL 도메인 (`https://` 제외) | **HTTPS only**, 포트 443 |

### 동작

| 경로 | 원본 | 캐시 정책 | 원본 요청 정책 | 함수 |
|---|---|---|---|---|
| `Default (*)` | s3-origin | **CachingOptimized** | — | — |
| `/booking` | alb-origin | **CachingDisabled** | **AllViewerExceptHostHeader** | 뷰어 요청 ▸ CF Function |
| `/v1/book` | lambda-origin | **CachingDisabled** | **AllViewerExceptHostHeader** | — |

메서드는 `/booking`, `/v1/book` 둘 다 **GET,HEAD,OPTIONS,PUT,POST,PATCH,DELETE** 로 허용.
기본값 루트 객체 **`index.html`**, 뷰어 프로토콜 **HTTP를 HTTPS로 리디렉션**.

### CloudFront Function

**CloudFront ▸ 함수 ▸ 함수 생성** (이름 예: `wsc2026-uri-rewrite`)

```javascript
function handler(event) {
  var request = event.request;
  if (request.uri === '/booking') { request.uri = '/v1/book'; }
  else if (request.uri === '/booking/') { request.uri = '/v1/book'; }
  return request;
}
```

**게시(Publish)** 후 `/booking` 동작의 **뷰어 요청**에 연결.

> 동작 매칭은 **원본 URI 기준**으로 먼저 일어나고, 그 다음 뷰어 요청 함수가 실행됩니다.
> 그래서 `/booking` → (동작 매칭) alb-origin → (함수) `/v1/book` 으로 재작성되어 ALB 규칙에 걸리고,
> `/v1/book` 요청은 별도 동작으로 Lambda 원본으로 갑니다. 두 경로가 충돌하지 않습니다.

## 13. [콘솔] 버킷 정책 + KMS 키 정책

배포 생성 직후 콘솔이 안내하는 **정책 복사(Copy policy)** 를 S3 ▸ 권한 ▸ 버킷 정책에 붙여넣습니다. (⏱ 즉시)

그리고 **KMS ▸ `wsc2026-bucket-kms` ▸ 키 정책 ▸ 편집** — 기존 Statement를 지우지 말고 아래를 **추가**:

```json
{
  "Sid": "Decrypt Role",
  "Effect": "Allow",
  "Principal": { "Service": "cloudfront.amazonaws.com" },
  "Action": ["kms:Decrypt", "kms:GenerateDataKey*"],
  "Resource": "*",
  "Condition": {
    "StringEquals": { "aws:SourceArn": "<CloudFront ARN>" }
  }
}
```

⏱ 저장 즉시 반영. 이미 403이 캐싱됐다면:
```bash
aws cloudfront create-invalidation --distribution-id $CF_ID --paths "/*"   # 1~2분
```

> `"kms:*"` 로 뭉뚱그리거나 root 프린시펄을 넣으면 `check_kms` 가 FAIL 입니다. 위처럼 액션을 명시하세요.
